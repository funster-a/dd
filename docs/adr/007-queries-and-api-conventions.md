# ADR 007. Запросы к базе и соглашения HTTP API

Статус: принято, 2026-09-28

## Контекст

Начинается бизнес-логика: у каждого модуля появляются запросы к PostgreSQL и HTTP-эндпоинты. Если не договориться заранее, модули начнут писать запросы и отвечать на ошибки каждый по-своему. Стек из `CLAUDE.md` задаёт pgx и sqlc.

## Решение

1. **Запросы — sqlc.** SQL пишется руками в `internal/<модуль>/queries.sql`, sqlc проверяет его по схеме из goose-миграций и генерирует типизированный Go-код в `internal/<модуль>/<модуль>db`. Сгенерированный код коммитится, CI проверяет его актуальность через `sqlc diff`. sqlc закреплён в `tools.mod`, как goose (ADR 002), команда — `make sqlc`.
2. **У каждого модуля свои запросы и свой сгенерированный пакет**, поэтому границы модулей (ADR 004) действуют и на уровне SQL.
3. **UUID в Go — строки** (переопределение типа в `sqlc.yaml`). Идентификаторы в коде не разбираются, только передаются, а строки не требуют отдельной зависимости.
4. **HTTP API.**
   - Версия в пути: `/v1/...`.
   - Тела запросов и ответов в JSON. Входящий JSON читается строго: неизвестные поля и лишние данные после объекта отклоняются, тело не больше 1 МБ.
   - Ошибки в едином формате `{"error": {"code": "...", "message": "..."}}`. `code` — машинно-читаемый, по нему фронтенд выбирает текст на нужном языке, `message` — для разработчика.
   - Аутентификация — заголовок `Authorization: Bearer <token>` (ADR 006).
   - Время в ответах — RFC 3339 в UTC, деньги — целые тиыны.

## Альтернативы

- **ORM (GORM, ent).** Скрывает SQL, а для ядра продажи мест важен именно точный SQL: блокировки, условия обновления, уникальные индексы. Отклонено.
- **SQL вручную через pgx.** Без проверки на этапе сборки: опечатка в имени колонки обнаружится только при выполнении. Отклонено.
- **Один сгенерированный пакет на весь проект.** Проще в настройке, но позволяет любому модулю вызвать любой запрос в обход границ. Отклонено.
- **Токен в HttpOnly cookie.** Надёжнее против XSS на сайте, но требует защиты от CSRF и неудобен для сканера и интеграций. На уровне API оставляем Bearer; как хранить токен в браузере, решим вместе с фронтендом.

## Следствия

- Первая сборка sqlc занимает около минуты: в нём парсер PostgreSQL на C, нужен компилятор C. Дальше сборка берётся из кэша.
- `models.go` каждого сгенерированного пакета содержит структуры всех таблиц: sqlc генерирует модели по всей схеме. Используются только нужные.
