# ADR 010. Кэш публичной страницы события

Дата: 2026-09-28. Статус: принято.

## Контекст

Публичную страницу события (карточка, площадка, цены, схема зала) открывают все покупатели. Больше всего открытий приходится на старт продаж: тысячи запросов в одну секунду. Схема зала на 50 тысяч мест — это сотни килобайт JSON, собранные из четырёх таблиц. Если каждый запрос будет собирать её заново, база упрётся в этот запрос раньше, чем в продажу мест.

После публикации страница почти не меняется: схема зала и цены зафиксированы, меняются только обложки.

## Решение

- Готовый JSON страницы хранится в Redis под ключом `catalog:public-event:{organizer}/{event}` с TTL 10 минут. Отдаётся как есть, без повторной сериализации.
- Одновременные промахи кэша по одному событию схлопываются в один запрос к базе через `singleflight` из `golang.org/x/sync`. Остальные запросы ждут его результат. Тест: 200 одновременных запросов при холодном кэше — одна загрузка из базы.
- Смена обложек сразу удаляет ключ. TTL нужен только как страховка от устаревших записей.
- «Не найдено» не кэшируется: иначе событие после публикации было бы недоступно до истечения TTL.
- Ошибка Redis не ломает страницу: она строится из базы.
- Ответ отдаётся с `Cache-Control: public, max-age=60`, чтобы его мог держать CDN.
- Свободные места в страницу не входят: они меняются каждую секунду и будут отдельным эндпоинтом модуля booking.
- `Cache` — интерфейс на стороне catalog. Реализация поверх Redis лежит в `platform/redis`.

## Альтернативы

- **Кэш в памяти процесса.** Быстрее Redis, но при нескольких экземплярах api у каждого своя копия. Сбрасывать их все при смене обложки пришлось бы через очередь. Возможный следующий шаг — второй уровень поверх Redis.
- **Своя реализация singleflight.** Это около 40 строк на mutex и map. `golang.org/x/sync` поддерживает команда Go, у пакета нет своих зависимостей, и он уже был в графе модулей транзитивно. Писать свою версию нет смысла.
- **Только HTTP-кэш или CDN.** Этот вариант не защищает базу при холодном CDN и не даёт мгновенно сбросить кэш.

## Следствия

- Изменение данных страницы должно сбрасывать кэш. Сейчас меняются только обложки, потому что после публикации схема и цены зафиксированы. При появлении редактирования опубликованного события сброс кэша нужно добавить туда.
- Новая прямая зависимость — `golang.org/x/sync`.
