# ADR 013. Контроль входа, бесплатные события и лимит билетов

Дата: 2026-09-29. Статус: принято.

## Контекст

По spec.md контроль входа сделан ссылками сканера:
- у контролёров нет учётных записей;
- организатор создаёт ссылку сканера для события и может её отозвать;
- сканер работает и без сети;
- при синхронизации засчитывается первое сканирование, повторное фиксируется как попытка прохода.

Бизнес-решения 2026-09-29:
- **Бесплатные мероприятия.** Нужны. Билеты на них не обязательны, но возможны.
- **Лимит билетов.** Выбор отдан технической стороне. Выбран лимит на покупателя за всё событие, чтобы перекупщик не набирал билеты несколькими заказами.

## Решение

### Ссылки сканера

- Организатор создаёт ссылку для события: `POST /v1/organizer/events/{id}/scanners`.
- Токен — 256 случайных бит, в базе хранится только SHA-256. Токен показывается один раз и лежит во фрагменте адреса (`/scan#<токен>`), поэтому не уходит на сервер при открытии страницы и не попадает в логи.
- Отозванная ссылка не принимается ни для списка билетов, ни для сканирований.
- API сканера: `/v1/scanner/*` с заголовком `Authorization: Scanner <токен>`. Middleware входа пропускает такой заголовок, не путая его с сессией.
- Маршруты ссылок живут в модуле ticket. Кабинет организатора монтирует catalog, поэтому `OrganizerRoutes` принимает регистрации других модулей и не знает о них.

### Работа без сети

- `GET /v1/scanner/manifest` отдаёт все билеты события: id, статус, место.
- QR содержит ссылку с токеном билета (ADR 012): id билета и HMAC от него. Секрет подписи сканеру не выдаётся: при утечке с телефона можно было бы подделывать билеты.
- Без сети сканер достаёт id из токена и ищет его в списке. Подобрать чужой id нельзя: в UUIDv7 74 случайных бита.

### Сканирования

- `POST /v1/scanner/scans` принимает одно сканирование онлайн или пачку до 500 после работы без сети.
- У каждого сканирования есть id от устройства. Уникальный индекс `(scanner_link_id, client_scan_id)` делает повторную отправку пачки после обрыва безопасной (правило 3).
- **Онлайн решает сервер.** Билет блокируется (`FOR UPDATE`), первое обработанное сканирование засчитывается, остальные получают «уже прошёл». Время онлайн-сканирования ставит сервер: часы телефона не могут перебить засчитанный проход. Сначала онлайн тоже учитывалось время устройства, и тест конкурентности поймал, что два контролёра могли оба получить «проход разрешён».
- **Офлайн засчитывается самое раннее сканирование** по времени устройства. Люди уже прошли, сервер только записывает итог. Более раннее офлайн-сканирование, пришедшее позже, становится засчитанным, а прежнее помечается повторной попыткой.
- Время из будущего (сбитые часы) заменяется временем сервера.
- Частичный уникальный индекс «один засчитанный проход на билет» держит правило на уровне схемы.
- Результаты:
  - `accepted` — проход засчитан;
  - `duplicate` — билет уже прошёл;
  - `revoked` — билет аннулирован;
  - `invalid` — не билет платформы или подделка;
  - `wrong_event` — билет другого события.

Экран сканера (PWA с камерой и очередью офлайн-сканирований) делается вместе с фронтендом на Vue (ADR 001). API для него готово.

### Бесплатные мероприятия

Два варианта:
1. **Свободный вход** (`admission = free_entry`): страница мероприятия без билетов, без схемы зала и цен. `seat_map_id` стал необязательным, CHECK требует схему только у событий с билетами. Цены и заказы на такое событие отклоняются, публикация не создаёт мест. На публичной странице `admission: free_entry` и `layout: null`.
2. **Бесплатные билеты:** категория с ценой 0. Заказ с суммой 0 оформляется сразу в той же транзакции: места `sold`, заказ `paid`, событие `order.paid` выпускает билеты тем же конвейером. Оплата не нужна. Можно смешивать с платными категориями: заказ с суммой больше нуля идёт через оплату.

### Лимит билетов

В заказе не больше мест, чем `max_tickets_per_buyer` минус уже купленные покупателем на это событие. Считаются места оплаченных заказов без возвращённых билетов. Одновременно два заказа одного покупателя не создать: одна корзина на событие (ADR 011).

## Альтернативы

- **Секрет подписи на сканере для офлайн-проверки.** Проще, но утечка с одного телефона позволяет печатать билеты. Отвергнуто.
- **Учётные записи контролёров.** Противоречит spec.md: один вход у организатора.
- **Время устройства и для онлайн-сканирований.** Отвергнуто после теста конкурентности, см. выше.
- **Свободный вход как событие с «пустой» схемой.** Организатору пришлось бы рисовать фиктивный зал для парка. Отвергнуто.
- **Лимит на заказ.** Не защищает от перекупщиков.

## Следствия

- Миграции 00009 (свободный вход) и 00010 (ссылки сканера, идемпотентность и один засчитанный проход).
- Откат 00009 возможен, только если нет событий со свободным входом.
- Nullable uuid в sqlc теперь `*string`, как остальные nullable-колонки.
