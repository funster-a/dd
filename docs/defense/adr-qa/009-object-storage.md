# ADR 009. Хранилище файлов — разбор к защите

Неделя 3 (26.10–01.11.2026). ADR: [`docs/adr/009-object-storage.md`](../../adr/009-object-storage.md).

## Суть в трёх фразах

У события есть обложка до 5 МБ и видеообложка до 15 МБ, и гонять такие файлы через api или хранить их в PostgreSQL на старте продаж нельзя. Решение — S3-совместимое хранилище: api выдаёт подписанную ссылку на 15 минут, браузер загружает файл по ней напрямую, а при прикреплении api проверяет в хранилище тип и размер файла. В базе лежит только ключ файла, обложку отдаёт само хранилище, а сменить сервер можно переменными `S3_*`.

Позже решение дополнили, механизм не меняли:
- ADR 016: кабинет загружает обложку через `XMLHttpRequest` с прогрессом; CORS SeaweedFS проверен вживую из собранного сайта под CSP (ADR 016:72-76);
- ADR 015: CSP сайта разрешает картинки только со своего адреса и из хранилища `MEDIA_ORIGIN` (ADR 015:56);
- ADR 030: хранилище — необязательная проверка `/readyz`, без него api отвечает 200 `degraded` (ADR 030:59-61; `cmd/api/main.go:222-231`);
- ADR 012 отложил PDF-билеты, которые ADR 009 называет будущими файлами хранилища.

## Почему так, а не иначе

- **MinIO как локальный сервер.** В 2025 году MinIO свернула распространение образов community-версии. В 2026 году образа нет в зеркалах, а `quay.io` закрыт в окружении разработки. Строить проект на продукте с такой политикой рискованно.
- **Garage.** Тоже открытый S3, но требует многошаговой настройки: раскладка кластера, ключи через CLI. Для локального запуска сложнее SeaweedFS, который поднимается одной командой `weed mini`.
- **AWS SDK v2.** Официальный клиент, но тяжелее по зависимостям при том же наборе операций. `minio-go` — клиент протокола S3 и работает с любым S3-сервером.
- **Загрузка через api.** Проще, но файл 15 МБ занимает соединение и память сервера ровно там, где важна производительность.
- **Файлы в PostgreSQL (`bytea`).** Раздувают базу и резервные копии, файл нельзя отдать через CDN.

## Чем подтверждено

- **Проверка при прикреплении.** `TestMediaUpload`, `internal/catalog/events_test.go:230-283`. Отклоняются неизвестный вид файла, GIF как обложка, картинка больше 5 МБ и видео больше 15 МБ. Не прикрепляется файл, которого нет в хранилище, файл с типом `text/html` вместо обещанного и ключ другого события. Хранилище в этом тесте — заглушка.
- **Настоящий путь браузера.** `TestUploadFlow`, `internal/platform/storage/storage_test.go:47-104`: ссылка, `PUT`, проверка размера и типа, чтение без подписи, отказ загрузки по подменённому ключу. Тест идёт против SeaweedFS и пропускается без `S3_TEST_ENDPOINT` (`storage_test.go:21-24`). CI поднимает SeaweedFS и задаёт эту переменную (`.github/workflows/ci.yml:86-99, 128`; `Makefile:66-68`).
- **Каталог не зависит от хранилища.** Интерфейс `ObjectStore` объявлен в каталоге (`internal/catalog/media.go:18-26`), адаптер к `platform/storage` — в `cmd/api/objectstore.go:14-33`.
- **Нагрузкой не мерилось.** В экспериментах обложки не загружались, в [реестре доказательств](../evidence.md) строк о хранилище нет.

## Вопросы комиссии

1. **Зачем отдельное хранилище, почему не хранить файлы в базе?**
   Ответ: В базе файлы раздувают таблицы и резервные копии, и их нельзя отдать через CDN. Через api 15 МБ занимали бы соединение и память на старте продаж. Поэтому в базе только ключ файла, сам файл лежит в бакете `dd-media`.
   Источник: ADR 009, «Контекст» (строка 7), «Решение» п. 1 (строка 11), «Альтернативы» (строки 27-28).

2. **Как браузер загружает файл, минуя api, и почему это безопасно?**
   Ответ: Первый запрос — `POST /events/{id}/media/uploads`: каталог проверяет вид, тип и размер и выдаёт ссылку `PUT` на 15 минут. Ключ генерирует сервер: префикс организатора, события и вида плюс случайная часть. Подпись привязана к ключу: ссылка с подменённым ключом не принимается. Ссылку получает только вошедший организатор.
   Источник: ADR 009, п. 2 (строки 12-15); `internal/catalog/media.go:42, 83-116`; `internal/platform/storage/storage_test.go:93-103`; `internal/catalog/http.go:64-66, 90-91`.

3. **Подписанная ссылка не ограничивает тип и размер. Что мешает загрузить по ней 1 ГБ или HTML?**
   Ответ: Ничего не мешает загрузить, но такой файл не прикрепится. При `PUT /events/{id}/media` каталог спрашивает у хранилища размер и тип файла и проверяет, что ключ выдан для этого события и этого вида. Если тип не из списка или размер больше лимита, ответ — ошибка проверки. Файл при этом остаётся в бакете до будущей очистки.
   Источник: ADR 009, п. 2 (строки 14-15), «Следствия» (строка 34); `internal/catalog/media.go:144-162`; `internal/catalog/events_test.go:254-267`.

4. **Почему SeaweedFS, а не MinIO, который все знают?**
   Ответ: MinIO в 2025 году свернула распространение образов community-версии: в 2026 году образа нет в зеркалах, а `quay.io` закрыт в окружении разработки. SeaweedFS под Apache 2.0 поднимается одной командой, бакет и правило анонимного чтения задаются конфигом в Compose. Код от выбора сервера не зависит: клиент `minio-go` говорит по протоколу S3.
   Источник: ADR 009, п. 6-7 (строки 19-20), «Альтернативы» (строка 24); `docker-compose.yml:77-92, 284-291`.

5. **Зачем два адреса, `S3_ENDPOINT` и `S3_PUBLIC_ENDPOINT`?**
   Ответ: api ходит в хранилище внутри сети Docker, а браузер — по внешнему адресу. Подпись S3 включает хост, поэтому ссылку для браузера подписывают публичным адресом, иначе подпись не совпадёт. Проверка файла идёт по внутреннему адресу.
   Источник: ADR 009, п. 4 (строка 17); `internal/platform/storage/storage.go:49-62, 80-98`; `docker-compose.yml:180-181`.

6. **Что не доказано и что будет, если хранилище недоступно?**
   Ответ: Без хранилища нельзя загрузить обложку, но страница события и продажа работают: адрес обложки строится из ключа без обращения к хранилищу, а `/readyz` отвечает 200 `degraded`. Загрузка под нагрузкой не мерилась. CDN перед хранилищем в проекте не настроен, на стенде обложки отдаёт сам SeaweedFS.
   Источник: `internal/platform/storage/storage.go:101-103`; ADR 030:59-61; `cmd/api/main.go:222-231`; ADR 009, п. 3 (строка 16).

## Где слабое место

- **CORS открыт для всех источников.** SeaweedFS по умолчанию отвечает на CORS-запросы с любого источника (ADR 009, строка 33). Почему приемлемо: на стенде нет внешних пользователей. Что дальше: для эксплуатации ограничить список доменом фронтенда.
- **Неприкреплённые файлы остаются в бакете.** Загруженный, но не прикреплённый файл никто не удаляет (строка 34). Это касается и файла, который не прошёл проверку типа или размера: проверка идёт после загрузки. Бакет открыт на чтение, поэтому такой файл доступен по прямому адресу. Почему приемлемо: ссылку получает только вошедший организатор, ключ лежит под его префиксом, ссылка живёт 15 минут. Что дальше: правило жизненного цикла бакета или фоновая очистка по сроку.
- **Тип при подписи не фиксируется.** Адаптер не передаёт тип файла в подпись (`cmd/api/objectstore.go:18-19`), поэтому единственный барьер — проверка при прикреплении. Ответ: так и записано в ADR (строка 15), проверка покрыта тестом.
- **Нет нагрузочного замера и CDN.** Отдача обложек под нагрузкой не мерилась, CDN не подключён. Ответ: обложки не проходят через api, поэтому на ядро продаж не влияют. CDN перед хранилищем потребует правки кода: сейчас и подпись ссылки, и публичный адрес обложки строятся от одного `S3_PUBLIC_ENDPOINT` (`internal/platform/storage/storage.go:54-60, 80-86, 101-103`), а для CDN нужен отдельный адрес чтения.
- **Только MP4 и WebM.** Конвертация GIF в видео не входит в MVP (строка 35).

## Проверь себя

1. Организатор получил ссылку для PNG на 2 МБ, а загрузил по ней HTML на 50 МБ. Что произойдёт при загрузке, при прикреплении и что останется в бакете?
2. Почему ссылку для загрузки подписывает клиент с публичным адресом, а размер файла спрашивает клиент с внутренним?
3. Что нужно сделать, чтобы перейти с SeaweedFS на облачный S3 в эксплуатации, кроме смены переменных `S3_*`?
