# Показ проекта на ноутбуке

Как поднять весь «Партер» на чистом ноутбуке и показать его: покупку билета с оплатой, бесплатный билет, план стадиона, кабинет организатора, контроль входа, возврат и метрики. Всё работает локально в Docker, внешних сервисов нет: оплата — мок платёжного провайдера, коды входа пишутся в лог.

## Что нужно

| | |
|---|---|
| Ноутбук | 8 ГБ памяти или больше, 10 ГБ свободного места. Intel, AMD и Apple Silicon — все образы есть под обе архитектуры |
| Docker | macOS и Windows — [Docker Desktop](https://www.docker.com/products/docker-desktop/), Linux — Docker Engine с плагином compose. Docker 24+, Compose 2.24+ |
| Память для Docker | в Docker Desktop: Settings → Resources → Memory не меньше 4 ГБ, лучше 6 |
| Git | чтобы скачать репозиторий; можно и без него — кнопка «Code → Download ZIP» на GitHub |
| Интернет | только на первый запуск: скачиваются образы, около 2 ГБ. Дальше всё работает без сети |

**Windows.** Docker Desktop работает поверх WSL 2. Удобнее всего всё делать внутри WSL: установите Ubuntu из Microsoft Store, откройте её терминал и выполняйте команды там. Так работают и команды с `grep` из этой инструкции.

Проверка, что Docker готов:

```sh
docker version
docker compose version
```

## Первый запуск — дома, с интернетом

```sh
git clone https://github.com/funster-a/dd.git
cd dd
docker compose up -d --build --wait
docker compose run --rm demo
```

Первая команда собирает образы и поднимает всё: PostgreSQL, Redis, RabbitMQ, хранилище файлов, два экземпляра api за балансировщиком, два воркера, сайт, мок оплаты, Prometheus и Grafana. В первый раз это 5–10 минут, дальше — около минуты. Команда возвращает управление, когда все сервисы здоровы.

Вторая команда заводит демо-данные и печатает адреса:

```
Демо-данные готовы. Сайт: http://localhost:8000

  Стендап-вечер, 02.11.2026
    http://localhost:8000/e/demo/standup
  Концерт на Центральном стадионе, 18.11.2026
    http://localhost:8000/e/demo/stadium-concert
  Открытая лекция (бесплатно, без оплаты), 26.10.2026
    http://localhost:8000/e/demo/open-lecture

Кабинет организатора: http://localhost:8000/org, вход по demo@example.com
```

Даты отсчитываются от дня запуска: лекция через неделю, стендап через две недели, стадион через месяц.

- **Стендап-вечер** — камерный зал на 126 мест: партер и балкон, первые три ряда дороже.
- **Концерт на Центральном стадионе** — план стадиона на 33 509 мест: сектора трибун и фан-зоны на поле.
- **Открытая лекция** — бесплатные билеты: билет выдаётся сразу, без оплаты.

Повторный запуск `docker compose run --rm demo` ничего не дублирует.

## Коды входа

Вход везде по одноразовому коду. SMS и письма в разработке не отправляются, код пишется в лог api. Перед показом откройте второй терминал и оставьте в нём:

```sh
docker compose logs -f api | grep --line-buffered one-time
```

После нажатия «получить код» на сайте в этом окне появится строка с кодом (поле `code`). В PowerShell без WSL вместо `grep` — `Select-String`:

```powershell
docker compose logs -f api | Select-String one-time
```

## Сценарий показа

Около десяти минут. Перед началом: Docker запущен, демо-данные заведены, второй терминал с кодами открыт. Под каждым шагом — что сказать комиссии.

### 1. Афиша

Откройте http://localhost:8000. На главной три события с обложками: открытая лекция, стендап-вечер и концерт на стадионе.

### 2. Покупка с оплатой

1. «Стендап-вечер» → «Выбрать места». Легенда схемы: «Первые ряды 8 000 ₸», «Партер 5 000 ₸», «Балкон 3 000 ₸» — цена зависит от ряда.
2. Нажмите два места в первом ряду. Внизу появится «2 билета 16 800 ₸» → «Оформить».
3. Окно «Вход по номеру телефона»: любой номер, например `+7 700 111 22 33` → «Получить код». Код появится во втором терминале; после шести цифр вход происходит сам.
4. «Оформление заказа»: заполните «Email для билетов» → «Перейти к оплате · 16 800 ₸».
5. Страница «Тестовый платёжный шлюз — деньги не списываются» → «Оплатить». Карта не нужна.
6. Сайт вернёт на страницу заказа: «Выпускаем билеты…», через 2–3 секунды — два билета с QR-кодами и пометкой «ДЕЙСТВИТЕЛЕН».
7. «Открыть билет ↗» — страница билета с QR. Скопируйте её адрес: он понадобится сканеру.

Что сказать:
- место держится за заказом 10 минут, и продать его второму покупателю нельзя ни при какой конкурентности — это главный инвариант проекта;
- в 16 800 ₸ входит сервисный сбор 5%, его платит покупатель, организатор не платит ничего;
- оплата — мок провайдера, карточные данные в платформу не попадают;
- за эти 2–3 секунды прошли вебхук провайдера, outbox, RabbitMQ и воркер, который выпустил билеты; повторный вебхук второй билет не создаст.

### 3. Бесплатный билет

«Открытая лекция» → «Выбрать места» → у «Свободная рассадка» нажмите «+» → «Оформить» → «Получить билеты». Билет выдаётся сразу, без страницы оплаты.

### 4. Стадион

«Концерт на Центральном стадионе» → «Выбрать места». План: сектора трибун и фан-зоны «Gold», «Silver», «Bronze» у сцены. Нажмите сектор — откроются его места; «← Все сектора» — назад к плану.

Что сказать: 33 509 мест. Штурм на 5 000 покупателей с очередью ожидания — все купили, двойных продаж ноль (`docs/defense/evidence.md`).

### 5. Кабинет организатора

Ссылка «Кабинет организатора →» внизу сайта или http://localhost:8000/org. «Рабочий email»: `demo@example.com` → «Получить код» → код из второго терминала. В списке три события «В продаже».

«Стендап-вечер» → вкладка «Продажи»: продано 2 места, выручка 16 000 ₸. Сбор 800 ₸ получает платформа, а не организатор. Кнопка «Скачать билеты · CSV» выгружает список для Excel.

### 6. Контроль входа

1. Вкладка «Контроль входа» → название, например «Вход А» → «Создать ссылку» → «Открыть здесь ↗». Откроется сканер контролёра.
2. Камеры на ноутбуке может не быть, это нормально: «Ввести код» → вставьте адрес билета из шага 2 → «Проверить».
3. Зелёный экран «✓ Проходите · Партер · ряд 1 · место 1». Нажмите на экран, чтобы закрыть результат.
4. Тот же билет ещё раз — «↺ Уже прошёл» и время первого прохода.

Что сказать: сканер работает и без сети. Он заранее скачивает список билетов, а после восстановления связи засчитывается самый ранний проход.

### 7. Возврат

«Мои билеты» → заказ «Стендап-вечер» → у второго билета «Вернуть» → подтвердите. Появится «Возврат 8 000 ₸ оформлен», билет получит метку «ВОЗВРАЩЁН», через пару секунд заказ станет «Частичный возврат». Место снова продаётся — это видно на схеме зала. Использованный билет вернуть нельзя: у него нет кнопки «Вернуть».

Что сказать: сбор при возврате по желанию покупателя не возвращается, при отмене события — возвращается. Повторное уведомление о возврате не освобождает место, если его уже купил другой.

### 8. Метрики

http://localhost:3000, вход `admin` / `admin`. На экране «Update your password» нажмите «Skip». Dashboards → папка «Партер» → «Партер: продажи и система»: попытки заказа, время оформления, обработка сообщений, PostgreSQL, Redis, RabbitMQ.

### 9. Отказ экземпляра api — по желанию

Пока открыт сайт, остановите один из двух экземпляров api:

```sh
docker kill $(docker compose ps -q api | head -1)
```

Сайт продолжает работать: балансировщик отправляет запросы на второй экземпляр. Вернуть: `docker compose up -d --wait`.

## На защите, без интернета

Всё нужное после первого запуска уже лежит на ноутбуке. В день показа заведите данные заново — так у событий будут свежие даты, а у покупок чистый лист:

1. Запустите Docker Desktop и подождите, пока он загрузится.
2. В папке проекта:
   ```sh
   docker compose down -v
   docker compose up -d --wait
   docker compose run --rm demo
   ```
   **Без `--build`**: сборка полезет в интернет за базовыми образами и без сети упадёт.
3. Откройте второй терминал с кодами входа (раздел выше) и вкладки браузера: сайт, кабинет, Grafana.

Если данные заведены давно, `docker compose run --rm demo` сам скажет, что события прошли, и попросит начать заново этими тремя командами.

Проверка накануне: выключите Wi-Fi и пройдите сценарий целиком.

После `git pull` с новыми изменениями образы нужно пересобрать, это требует интернета: `docker compose up -d --build --wait` и `docker compose run --rm --build demo`.

## Если что-то не так

| Что видно | Что сделать |
|---|---|
| `429 Too Many Requests` при первой сборке | лимит анонимных скачиваний Docker Hub: `docker login` или подождать |
| `port is already allocated` | порт занят другой программой (часто 5432 — свой PostgreSQL, 3000 — dev-сервер). `cp .env.example .env` и поменять нужный `*_PORT` |
| Сервис не становится здоровым | `docker compose ps` покажет какой, `docker compose logs <сервис>` — почему. Часто не хватает памяти Docker Desktop |
| Нет кода входа | второй терминал запущен из папки проекта? `docker compose logs api \| grep one-time` покажет все выданные коды |
| После оплаты нет билетов | билеты выпускает воркер: `docker compose ps worker`, `docker compose logs worker` |
| На сайте нет событий | демо-данные не заведены: `docker compose run --rm demo`. Афиша может обновиться через несколько секунд — у неё кэш на краю |
| Всё сломалось | `docker compose down -v`, затем три команды из раздела выше |

Остановить, сохранив данные: `docker compose down`. Удалить вместе с данными: `docker compose down -v`.
