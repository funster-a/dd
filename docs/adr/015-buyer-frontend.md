# ADR 015. Сайт покупателя

Дата: 2026-09-30. Статус: принято.

## Контекст

Бэкенд MVP готов: каталог, бронирование, оплата, билеты, возвраты. Покупателю нужен сайт: афиша, страница события со схемой зала, оформление заказа, оплата, билеты и возврат. Стек фронтенда задан ADR 001: Vue, TypeScript, Vite.

Требование к дизайну от заказчика: красиво, современно и без «шаблонного ИИ-стиля». Значит, без фиолетовых градиентов, стеклянных карточек, эмодзи в заголовках и одинаковых скруглённых блоков.

Кабинет организатора и экран сканера в вебе — следующий этап. API для них уже есть.

## Решение

### Приложение

- Vue 3 (Composition API, `<script setup>`), vue-router, TypeScript в строгом режиме с `noUncheckedIndexedAccess`.
- Без UI-библиотеки и без менеджера состояний. Общего состояния мало: сессия и уведомления. Его держат модульные `reactive` в `composables/`. Корзина живёт на странице события.
- Экраны грузятся лениво по маршрутам. Сборка: основной JS ~45 КБ gzip, страница события ~7 КБ.

| Маршрут | Экран |
|---|---|
| `/` | афиша: `GET /v1/public/events` |
| `/e/{org}/{slug}` | событие, схема зала, корзина, оформление |
| `/payment/return` | возврат от провайдера, переход на заказ |
| `/orders/{id}` | заказ: оплата с таймером холда, билеты с QR, возврат |
| `/me` | мои билеты: `GET /v1/me/orders` |
| `/t/{token}` | билет по подписанной ссылке, без входа |

### Два новых эндпоинта

- `GET /v1/public/events` — ближайшие опубликованные события (до 60 штук) с минимальной ценой. Без входа, `Cache-Control: max-age=30`.
- `GET /v1/me/orders` — заказы покупателя с названием и датой события, без отменённых и просроченных (до 100 штук).

Оба эндпоинта только читают данные и живут в модулях, которые владеют таблицами (catalog и booking).

### Схема зала

- SVG, а не canvas. Каждое место — отдельный элемент с `role="button"`, `aria-label` («Партер, ряд 3, место 11, 12 000 ₸»), фокусом с клавиатуры, Enter и пробелом. Залы MVP — сотни и тысячи мест, SVG с этим справляется.
- Если у всех мест сектора есть координаты из редактора, место рисуется по ним. Иначе ряды раскладываются автоматически.
- Цвет места — ценовая категория. Занятое место — серое с крестиком.
- На телефоне схема сначала вписывается в ширину, дальше её увеличивают кнопками, центр при этом сохраняется.
- Модель схемы и корзина (`lib/seatmap.ts`) — чистые функции с юнит-тестами: раскладка, лимит билетов на покупателя, входные зоны.
- Занятость обновляется раз в 15 секунд, пока вкладка видима. Место, которое заняли, пока покупатель выбирал, уходит из корзины. Истина о занятости — только у сервера: при `seat_taken` схема обновляется, покупатель видит объяснение.

### Оформление и оплата

- Вход по телефону в нижней панели, только когда он нужен: при нажатии «Оформить». Код из 6 цифр отправляется автоматически.
- Ключ идемпотентности создаётся на одну попытку оформления. Повтор после обрыва связи не создаёт второй заказ (ADR 008).
- Бесплатный заказ сразу ведёт на страницу заказа. Платный — на страницу провайдера (`payment_url`). После возврата страница заказа опрашивает статус, пока вебхук не подтвердит оплату, и ждёт выпуска билетов воркером.

### Развёртывание

- В Docker сайт отдаёт nginx (`web/Dockerfile`: сборка на node:24, раздача на nginx:1.29-alpine). nginx проксирует `/v1` в api. Браузер работает с одним origin: без CORS, cookie и токен не уходят на чужой домен.
- `PUBLIC_BASE_URL` в compose указывает на сайт (`http://localhost:8000`). Ссылки на билеты и возврат после оплаты ведут в SPA.
- Заголовки: CSP (`script-src 'self'`, картинки только свои и из S3 `MEDIA_ORIGIN`, `frame-ancestors 'none'`), `nosniff`, `Referrer-Policy`. Файлы с хешем в имени кэшируются навсегда, `index.html` — `no-cache`.
- В разработке Vite проксирует `/v1` в api на `:8080`.

### Дизайн

Язык — афиша и журнал, а не «приложение». Тёплая бумага и чернила, один яркий акцент (киноварь `#ff4d1f`), крупный гротеск Onest для заголовков, курсив Playfair Display для одной акцентной строки, моноширинный JetBrains Mono для дат, цен и технических подписей. Билет выглядит как корешок: вырезы на линии отрыва и перфорация. Есть тёмная тема по системной настройке.

Шрифты подключены через `@fontsource`, собираются вместе с сайтом и не грузятся с чужих серверов. Вариант с Google Fonts отклонён: лишний запрос к третьей стороне и ослабление CSP.

Доступность: ссылка «к содержимому», видимый фокус, подписи для экранного диктора, `prefers-reduced-motion`.

### Зависимости

| Пакет | Зачем |
|---|---|
| `vue`, `vue-router` | фреймворк (ADR 001) |
| `@fontsource-variable/onest`, `@fontsource/jetbrains-mono`, `@fontsource/playfair-display` | шрифты локально, без запросов к третьим сторонам |
| dev: `vite`, `@vitejs/plugin-vue`, `typescript`, `vue-tsc`, `@vue/tsconfig` | сборка и проверка типов |
| dev: `vitest`, `jsdom`, `@vue/test-utils` | юнит-тесты |

TypeScript закреплён на 5.9. TypeScript 7 пока несовместим с `vue-tsc`.

## Альтернативы

- **Nuxt с SSR.** SEO-выигрыш для афиши есть, но нужен ещё один Node-процесс в проде. Страница события и так кэшируется на бэкенде. Отложено до появления требования к SEO.
- **UI-библиотека (Vuetify, PrimeVue).** Быстрее собрать формы, но узнаваемый «библиотечный» вид противоречит требованию к дизайну. Компонентов мало, они свои.
- **Canvas для схемы зала.** Быстрее на десятках тысяч мест, но без доступности и с ручной обработкой кликов. Для залов MVP не нужен.
- **Раздача SPA из api на Go.** На один контейнер меньше, но смешивает сборку фронтенда со сборкой бэкенда. nginx даёт кэш статики и заголовки без кода.

## Следствия

- В compose новый сервис `web` на порту 8000, в CI новая задача Web (типы, тесты, сборка), а compose-тест проверяет раздачу сайта, прокси и CSP.
- `PUBLIC_BASE_URL` в Docker теперь адрес сайта. Страницы `/t/{token}` и `/payment/return` в api остаются для работы без фронтенда.
- По ходу найдена и исправлена ошибка бэкенда: после возврата место освобождалось в базе, но холд оплаченного заказа в Redis ещё до 10 минут не давал его купить. Теперь `ApplyRefund` снимает ключи холдов.
